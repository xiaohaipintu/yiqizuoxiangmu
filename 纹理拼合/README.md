# 纹理拼合 · 生成正方形图 → 切 9 块 → 按纹理拼回

纯前端单文件，双击 `index.html` 或访问 http://127.0.0.1:8002/ 即可。

## 它做什么

1. **生成**一张 600×600 的正方形图（渐变底 + 46 个随机色块 + 60 条随机斜线，故意让形状跨越切缝）；
2. **切分**成 3×3 = 9 块，每块 200×200；
3. **打乱**成随机排列（保证不是原序）；
4. **纹理检测拼合**：**不看位置、不知道原图排布**，只比较相邻两块边缘像素的连续性，搜出接缝代价最小的排列。

## 纹理检测怎么算

对每一块取它四条边的像素（`L / R / T / B`），两两计算接缝代价：

```
横缝(a 在左, b 在右) = mean( (a.R - b.L)² )     ← 逐行逐通道
竖缝(a 在上, b 在下) = mean( (a.B - b.T)² )
```

同一张图切开的相邻两块，边缘列本来就是相邻像素，代价极小；不相关的两块是随机颜色，代价大一个数量级。

然后**分支限界**搜索：按行优先逐格填，每填一格就把「左边缝 + 上边缝」的代价累加，一旦超过当前最优就剪枝。等价于遍历所有 9! = 362880 种排列，但因为正确解的代价接近 0，剪枝极狠，实际 **< 1 ms**。

## 页面显示

- 左：打乱后的 9 块（`#编号` 可切换显示，用来核对）；
- 右：拼合结果，并画出 12 条接缝（**越绿 = 代价越小 = 越像同一张图切开的**）；
- 下方：总接缝代价、平均每条缝、与「任意两块硬拼的代价中位数」的倍数（倍数越大越确信）。

因为图是自己生成的，正确答案一定是 `0..8`，所以能直接判定对不对。

## 已知限制

- 只处理 3×3 且**不允许旋转/翻转**（只做平移）。如果允许旋转，每个格子多 4 种朝向，搜索空间 ×4^9，需要换更好的剪枝或回溯策略。
- 如果图本身有大面积纯色（比如一半是天空），那条缝的代价对谁都差不多，靠边信息就分不出来 —— 这也是为什么生成图里故意撒了大量随机色块和斜线。
